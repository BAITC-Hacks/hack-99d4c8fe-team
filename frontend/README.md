# Искра — каталог бизнес-задач и предложений команд

Frontend-прототип на Next.js 15, TypeScript и Tailwind CSS 4. Интерфейс и логика разделены по feature-папкам.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Production-проверка: `npm run build`.

## Реализованные сценарии

- Публичный каталог задач с цветами по категории, сортировкой по рейтингу/дате/откликам, фильтрами по теме и готовности.
- Владелец может удалить свою задачу из окна подробностей.
- Конструктор: свободное описание, три блока вопросов, получаемых с backend, проверка готовности по `ready`, редактируемая карточка.
- Отдельный шаг ручного подтверждения перед публикацией. Требуется рейтинг не менее 40/100.
- Рейтинг 0–100 с расшифровкой критериев и недостающих сведений; пересчёт во время редактирования и после публикации.
- В карточке задачи отображаются контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия.
- Команда отправляет название, идею решения, план и необязательную ссылку на прототип. Отклики не ограничены по количеству.
- Автор вручную выбирает или отклоняет каждое предложение. Автоматического назначения команды нет.
- Данные прототипа хранятся в localStorage текущего браузера.

```text
    ├── types.ts                 # Task, TaskFields, TeamResponse

    ├── lib/rating.ts            # критерии, баллы, готовность
    ├── lib/api.ts               # запросы черновика, уточнений, публикации и удаления
    ├── lib/api.ts               # запросы черновика, уточнений, публикации и удаления
    └── components/
        ├── TaskCard.tsx         # карточка в общем каталоге
        ├── TaskBuilder.tsx      # три раунда, предпросмотр, подтверждение
        ├── TaskEditor.tsx       # редактор опубликованной карточки

```

## Backend API для конструктора

Скопируйте `.env.example` в `.env.local` в корне проекта и укажите в `NEXT_PUBLIC_API_BASE_URL` адрес своего backend, например `http://localhost:8000`. После изменения `.env.local` перезапустите `npm run dev`. Без доступного API отправка формы покажет сообщение об ошибке; вопросы локально не подменяются.

Ожидаются следующие endpoints:

1. `POST /api/task-drafts` — тело `{ "title": "...", "description": "...", "category": "..." }`; ответ `{ "draftId": "...", "questions": [{ "id": "q1", "text": "...", "placeholder": "..." }] }`.
2. `POST /api/task-drafts/:draftId/answers` — тело `{ "round": 1, "answers": [{ "questionId": "q1", "answer": "..." }] }`; backend возвращает `{ "ready": false, "questions": [...] }` для следующего блока либо `{ "ready": true, "finalText": "...", "taskFields": { ... }, "rating": 82 }` после уточнений. Если `ready` равно `false`, обязательно верните вопросы для продолжения.
3. `GET /api/tasks` — общий публичный каталог опубликованных задач.
4. `DELETE /api/tasks/:taskId` — удаляет задачу владельца. Frontend вызывает этот endpoint для задач, опубликованных backend.
5. `POST /api/task-drafts/:draftId/publish` — тело `{ "category": "...", "fields": { ... }, "finalText": "...", "useGeneratedText": true }`; ответ может содержать `{ "task": { "id": "...", "rating": 82, ... } }`.

На последнем шаге автор выбирает итоговый текст backend или исходное описание и может отредактировать выбранный вариант перед подтверждением публикации. Backend должен проверить готовность, рейтинг, права владельца и статус откликов. Общий каталог запрашивается через `GET /api/tasks`; браузер хранит локальную копию публикаций создателя. Отклики пока хранятся в localStorage; подключите `PATCH /api/tasks/:id`, `DELETE /api/tasks/:id`, `POST /api/tasks/:id/responses`, `PATCH /api/tasks/:id/responses/:responseId`.
