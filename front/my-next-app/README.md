# Искра — каталог бизнес-задач и предложений команд

Frontend-прототип на Next.js 15, TypeScript и Tailwind CSS 4. Интерфейс и логика разделены по feature-папкам.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Production-проверка: `npm run build`.

## Реализованные сценарии

- Публичный каталог задач, сортировка по рейтингу, фильтры по теме и готовности.
- Конструктор: свободное описание, три раунда уточнений, проверка полноты, редактируемая карточка.
- Отдельный шаг ручного подтверждения перед публикацией. Требуется рейтинг не менее 40/100.
- Рейтинг 0–100 с расшифровкой критериев и недостающих сведений; пересчёт во время редактирования и после публикации.
- В карточке задачи отображаются контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия.
- Команда отправляет название, идею решения, план и необязательную ссылку на прототип. Отклики не ограничены по количеству.
- Автор вручную выбирает или отклоняет каждое предложение. Автоматического назначения команды нет.
- Данные прототипа хранятся в localStorage текущего браузера.

## Архитектура

```text
src/
├── app/
│   ├── page.tsx                 # страницы и координация действий
│   └── globals.css              # общие стили и стили feature-компонентов
└── features/tasks/
    ├── types.ts                 # Task, TaskFields, TeamResponse
    ├── data.ts                  # демонстрационные опубликованные задачи
    ├── lib/rating.ts            # критерии, баллы, готовность
    └── components/
        ├── TaskCard.tsx         # карточка в общем каталоге
        ├── TaskBuilder.tsx      # три раунда, предпросмотр, подтверждение
        ├── TaskEditor.tsx       # редактор опубликованной карточки
        ├── TaskDetails.tsx      # подробности, отклики, ручной выбор команды
        └── RatingBreakdown.tsx  # рейтинг, начисленные баллы, пробелы
```

## Подключение backend

Замените обращения к localStorage на сервисный слой с методами `listTasks`, `createDraft`, `answerClarificationRound`, `publishTask`, `updateTask`, `submitTeamResponse` и `setResponseStatus`. Рекомендуемый API: `GET /api/tasks`, `POST /api/task-drafts`, `POST /api/task-drafts/:id/answers`, `POST /api/task-drafts/:id/publish`, `PATCH /api/tasks/:id`, `POST /api/tasks/:id/responses`, `PATCH /api/tasks/:id/responses/:responseId`. Подсчёт оценки и права на публикацию/выбор команды сервер должен проверять повторно. Сейчас список задач и данные формы демонстрационные и хранятся локально.
