# Искра — Next.js + FastAPI

**Искра** — веб-прототип, который помогает бизнесу превратить исходную потребность в понятную задачу для студенческой команды. Автор описывает проблему, отвечает на уточняющие вопросы, проверяет карточку и публикует её в каталоге. Команды изучают задачи и предлагают решения.

Проект помогает уточнить то, чего часто не хватает в постановке задачи: аудиторию, ресурсы, ограничения, ожидаемый результат и критерии успеха. Целевая аудитория — авторы бизнес-задач и студенческие команды, ищущие практические проекты.

**Посетителю не нужен собственный API-ключ:** backend использует встроенный сценарий либо серверный ключ OpenAI.

> Документация сверена со снимком `main` — `8e2a1db`. В нём уже есть SQLite и проверка владельца, но подключение frontend к обновлённому backend и Docker-конфигурация ещё требуют доработки. Ниже эти ограничения отделены от реализованных серверных возможностей.

## Что реализовано

| Возможность | Текущее состояние |
| --- | --- |
| Каталог | Демонстрационные карточки и загрузка серверных публикаций |
| Поиск и фильтры | Поиск по названию, контексту, потребности и категории; фильтры по тематике и готовности |
| Сортировка | По рейтингу, дате и числу откликов |
| Конструктор | Исходное описание, три блока уточнений, проверка готовности, редактируемая карточка |
| Работа без ключа | Встроенные вопросы и перенос ответов в поля карточки |
| OpenAI | Генерация вопросов и оценка ответов; резервный сценарий в режиме `auto` |
| Публикация | Ручное подтверждение, сохранение в SQLite, общий каталог |
| Операции автора | Backend проверяет владельца черновика и задачи |
| Отклики и редактирование | Серверные маршруты реализованы; существующие формы frontend пока сохраняют эти изменения локально |

Карточка содержит название, контекст, потребность, пользователей, данные, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия. В интерфейсе предусмотрены выбор и отклонение предложений автором. Автоматического назначения исполнителя нет.

## Как работает решение

1. Автор вводит название, описание и категорию задачи.
2. Backend создаёт черновик, закрепляет его за посетителем через cookie и выбирает источник вопросов.
3. Автор проходит три блока: проблема и пользователи; данные и ограничения; результат, критерии успеха, контакт и формат работы.
4. При `ready: true` открывается редактируемая карточка. В режиме OpenAI формулировки зависят от модели; при недостатке сведений возможны дополнительные уточнения в третьем блоке.
5. Автор выбирает подготовленный или исходный текст, вносит правки и подтверждает публикацию.
6. Backend сохраняет задачу в SQLite и пересчитывает рейтинг по заполненным полям.
7. Команда заполняет предложение решения. Чтобы оно передавалось другому посетителю через сайт, необходимо подключить существующий серверный маршрут к форме frontend.

### Режимы уточнения

| `AI_MODE` | Поведение |
| --- | --- |
| `auto` — по умолчанию | Использует серверный `OPENAI_API_KEY`, если он задан; при отсутствии ключа или ошибке вызова внешнего сервиса переходит к встроенному сценарию |
| `demo` | Три фиксированных блока без внешнего сервиса и ключа |
| `openai` | Только OpenAI; без рабочего серверного ключа запрос возвращает ошибку |

Встроенный сценарий не генерирует вопросы по смыслу текста. Он содержит 2, 2 и 4 вопроса в трёх блоках, переносит ответы в поля и рассчитывает заполненность карточки.

Промпты находятся в `backend/app/services/ai_service.py` и содержат TODO-заготовки, которые нужно доработать для содержательной AI-демонстрации. Модель задаётся через `OPENAI_MODEL`; по умолчанию — `gpt-4.1-mini`.

## Технологии

## Архитектура

```text
Браузер — Next.js / React
  ├── Каталог, конструктор, редактор, предложения команд
  ├── localStorage: локальные копии, правки и отклики
  └── HTTP / JSON → FastAPI
                      ├── Валидация и проверка владельца по cookie
                      ├── SQLite: черновики, задачи, серверные отклики
                      └── Выбор режима
                            ├── Встроенные вопросы
                            └── OpenAI Responses API
```

Frontend использует `NEXT_PUBLIC_API_BASE_URL`, а без значения отправляет запросы на `/api/*` текущего сайта. **Проксирование этих путей в `next.config.ts` пока отсутствует.** Необходимая настройка приведена в разделе запуска.

```text
.
├── frontend/
│   ├── next.config.ts             # пока без прокси API
│   └── src/
│       ├── app/page.tsx           # каталог и локальное состояние
│       └── features/tasks/
│           ├── components/       # конструктор, карточка, редактор, отклики
│           ├── lib/api.ts        # обращения к backend
│           ├── lib/rating.ts     # оценка заполненности
│           ├── data.ts           # демонстрационные задачи
│           └── types.ts
├── backend/
│   ├── app/
│   │   ├── main.py               # маршруты и cookie владельца
│   │   ├── schemas.py            # контракты данных
│   │   ├── storage.py            # SQLite
│   │   └── services/
│   │       ├── clarification.py  # выбор auto / demo / openai
│   │       ├── demo_service.py   # встроенный сценарий
│   │       └── ai_service.py     # OpenAI и промпты
│   ├── data/iskra.db
│   ├── tests/test_task_flow.py
│   ├── .env.example
│   └── Dockerfile
├── compose.yaml
└── .github/workflows/ci.yml
```

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Проверка backend и подключения к SQLite |
| `POST /api/task-drafts` | Создание черновика и первого блока |
| `POST /api/task-drafts/{draft_id}/answers` | Отправка ответов |
| `POST /api/task-drafts/{draft_id}/publish` | Публикация готового черновика |
| `GET /api/tasks` | Общий каталог с учётом владельца |
| `PATCH /api/tasks/{task_id}` | Редактирование владельцем |
| `DELETE /api/tasks/{task_id}` | Удаление владельцем |
| `POST /api/tasks/{task_id}/responses` | Сохранение предложения команды |
| `PATCH /api/tasks/{task_id}/responses/{response_id}` | Решение автора по предложению |

## Установка и запуск

### Получение проекта

Нужны Git, доступ к репозиторию, Node.js 22 и Python 3.12. Встроенный сценарий не требует ключа внешнего сервиса.

```powershell
git clone https://github.com/BAITC-Hacks/hack-99d4c8fe-team.git
cd hack-99d4c8fe-team
```

### Backend на Windows

В первом терминале, из корня проекта:

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:AI_MODE = 'demo'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

`demo` обеспечивает воспроизводимую проверку без обращения к внешнему сервису. Для автоматического выбора источника задайте `AI_MODE=auto`.

- Backend: [http://localhost:8000/api/health](http://localhost:8000/api/health), ожидается `{"status":"ok"}`.
- Интерактивная документация: [http://localhost:8000/docs](http://localhost:8000/docs).

### Подключение frontend

Для полного сценария через браузер **замените содержимое `frontend/next.config.ts` следующей конфигурацией**. Это необходимая доработка проверенного снимка, а не уже существующая настройка:

```typescript
import type { NextConfig } from 'next';

const backendUrl = (process.env.BACKEND_URL || 'http://127.0.0.1:8000').replace(/\/$/, '');

const nextConfig: NextConfig = {
  async rewrites() {
    return [{ source: '/api/:path*', destination: `${backendUrl}/api/:path*` }];
  },
};

export default nextConfig;
```

Во втором терминале, из корня проекта:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). После добавления прокси проверка через сайт доступна по адресу [http://localhost:3000/api/health](http://localhost:3000/api/health).

При этой конфигурации `frontend/.env.local` не нужен. Если ранее задавали `NEXT_PUBLIC_API_BASE_URL`, удалите его значение из окружения и `.env.local`, затем перезапустите frontend: запросы должны идти через `/api/*` своего сайта. Так браузер передаёт cookie владельца в последующих запросах.

Без прокси доступен демонстрационный каталог, но полный конструктор через сайт не подключён. Простого указания другого origin в `NEXT_PUBLIC_API_BASE_URL` также недостаточно: текущий клиент не задаёт `credentials: 'include'` для передачи cookie между origin.

### Серверный ключ OpenAI

Создайте `backend/.env` вручную:

```dotenv
AI_MODE=auto
OPENAI_API_KEY=YOUR_SERVER_KEY
OPENAI_MODEL=gpt-4.1-mini
FRONTEND_ORIGIN=http://localhost:3000
DATABASE_PATH=./data/iskra.db
COOKIE_SECURE=false
```

Если в терминале уже задан `$env:AI_MODE = 'demo'`, измените его на `auto` или удалите эту переменную перед перезапуском backend: переменные процесса имеют приоритет над `.env`.

Ключ читает только backend. Не помещайте его в frontend, `NEXT_PUBLIC_*` или Git. В проверенном `backend/.env.example` обнаружено значение, похожее на секретный ключ: не используйте его; если ключ действующий, владелец должен отозвать и заменить его.

Для строгой проверки внешней модели используйте `AI_MODE=openai`. В режиме `auto` успешный сценарий может быть результатом встроенного резервного режима.

### Docker Compose

В `compose.yaml` описаны backend, frontend и постоянный том SQLite `iskra-data`. Однако **`docker compose up --build` пока не является готовым способом запуска всего проекта**: отсутствует `frontend/Dockerfile`, а `BACKEND_URL` не используется исходным `next.config.ts`.

После добавления Dockerfile frontend и проксирования API предполагаемый запуск из корня проекта:

```bash
docker compose up --build
```

Compose задаёт backend `AI_MODE=auto`, поэтому ключ не обязателен. Для OpenAI можно создать `.env` в корне проекта с `OPENAI_API_KEY=...`; Compose передаёт ключ только backend. Frontend предполагается доступным на порту 3000, backend отдельно наружу не публикуется.

Остановка: `Ctrl+C`, затем:

```bash
docker compose down
```

Обычный `down` сохраняет именованный том. Удаление тома приводит к потере базы.

## Как проверить решение

### Основной сценарий без ключа

1. Запустите backend с `AI_MODE=demo` и frontend с прокси по инструкции выше.
2. Проверьте `/api/health` через порт 3000.
3. Нажмите **«Создать задачу»**, выберите «Экология», укажите название **«Учёт остатков в столовой»** и описание **«В столовой кампуса остаётся еда, но объём списаний не фиксируется. Нужен простой инструмент учёта.»**
4. Заполните три блока, например:

   | Поле | Тестовый ответ |
   | --- | --- |
   | Проблема | Нет единого учёта остатков по блюдам |
   | Пользователи | Сотрудники столовой и администратор |
   | Данные | Обезличенная таблица списаний за неделю |
   | Ограничения | Две недели на прототип, без нового оборудования |
   | Результат | Форма ввода остатков и недельный отчёт |
   | Критерий успеха | Сотрудник вводит запись и получает сводку за неделю |
   | Контакт | demo@example.com |
   | Взаимодействие | Еженедельная встреча с командой |

5. После третьего блока проверьте карточку, измените текст и нажмите **«Подтвердить и опубликовать»**.
6. Проверьте появление задачи в каталоге, разделе «Мои задачи» и ответе `GET /api/tasks`.
7. Перезапустите backend с тем же файлом базы. Серверная публикация должна сохраниться.
8. Удалите тестовую задачу в браузере автора и проверьте её отсутствие в серверном каталоге.

Встроенный сценарий при заполнении всех десяти полей даёт 100/100. Это оценка заполненности, а не качества идеи.

### Отклики и права владельца через API

Серверную часть можно проверить через [Swagger UI](http://localhost:8000/docs), создав и опубликовав задачу там в одном браузере: он получит cookie владельца.

1. В другом браузере отправьте `POST /api/tasks/{task_id}/responses` с названием команды, идеей и планом.
2. В браузере автора получите каталог: у задачи должен появиться отклик.
3. В браузере автора измените статус через `PATCH /api/tasks/{task_id}/responses/{response_id}`.
4. Попытка удалить задачу из браузера без cookie владельца должна вернуть HTTP 403.

Форма предложения на сайте пока выполняет локальную операцию и не заменяет серверную проверку. Изменения встроенных карточек `sample-*` не сохраняются при перезагрузке страницы.

### Проверки кода

В каталоге `frontend`:

```powershell
npm run format:check
npm run lint
npm run typecheck
npm run build
```

В каталоге `backend`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m ruff format --check app tests
.\.venv\Scripts\python.exe -m ruff check app tests
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты покрывают три блока, публикацию, удаление, режим без ключа, резервный сценарий при ошибке провайдера, права владельца, серверные отклики, чтение сохранённых данных новым клиентом и ошибку подключения к базе. Они не подтверждают качество реальных ответов OpenAI.

## Данные и интеграции

- **Пользовательский ввод:** описание, ответы, поля карточки, контакты и предложения команд.
- **Демонстрационные данные:** три задачи в `frontend/src/features/tasks/data.ts`. Показатели в них — примеры, а не результаты эксплуатации.
- **OpenAI:** получает данные задачи и ответы при использовании внешней модели. В `demo` обращения к OpenAI отсутствуют.
- **SQLite:** хранит черновики, публикации, владельцев и отклики, отправленные через API. Путь по умолчанию — `backend/data/iskra.db`, переопределяется через `DATABASE_PATH`.
- **Cookie `iskra_owner`:** случайный токен посетителя, HttpOnly, SameSite=Lax; на сервере хранится его хеш для проверки владельца.
- **localStorage:** локальные копии задач, правки и предложения frontend сохраняются под ключом `iskra-tasks-v2`.

Интеграции с CRM, автоматическая загрузка датасетов и уведомления не реализованы. «Данные и материалы» — текстовое поле.

## Ограничения

- **Подключение frontend требует настройки.** Прокси отсутствует; конфигурация для локального запуска приведена выше. Docker-сборка frontend не завершена.
- **Интерфейс подключён к API частично.** Backend поддерживает правки и отклики, но соответствующие действия frontend пока меняют localStorage. Локальная копия может скрывать обновлённую серверную карточку при объединении каталога.
- **Нет учётных записей и восстановления доступа.** Права автора привязаны к cookie браузера. При её утрате нет входа в аккаунт для восстановления прав.
- **Demo не выполняет смысловой анализ.** Вопросы фиксированы; высокий рейтинг означает заполненность полей.
- **AI-промпты требуют доработки.** В коде сохранены TODO-заготовки; качество генерации не измерено. В `auto` ошибки внешнего сервиса могут скрываться за успешным встроенным сценарием.
- **Рейтинг при публикации пересчитывается.** Модель может вернуть свою оценку при уточнениях, но опубликованная карточка получает серверную оценку заполненности.
- **Нет лимитов запросов и защиты от спама откликами.** Серверный маршрут предложений не требует учётной записи команды.
- **SQLite требует сохранного диска.** Перезапуск backend не удаляет публикации при сохранении файла базы. Потеря файла или Docker-тома означает потерю данных; резервное копирование не настроено.
- **Нет подтверждённых метрик эксплуатации:** нагрузки, точности AI или эффективности сотрудничества.

## Размещение и deployed-версия

Подтверждённая публичная ссылка на работающий сайт в проверенных файлах не найдена.

Для размещения нужны Next.js сервер и постоянный Python процесс. После добавления прокси задайте `BACKEND_URL` при сборке frontend — адрес FastAPI, доступный серверу Next.js. Посетителям достаточно публичного адреса frontend; backend можно оставить во внутренней сети.

На сервере задайте `AI_MODE=auto` и, если нужна модель, секретный `OPENAI_API_KEY`. Для HTTPS включите `COOKIE_SECURE=true`. Обеспечьте постоянный диск SQLite. Перед работой с реальными пользователями завершите подключение форм к API, предусмотрите восстановление доступа автора, резервное копирование и лимиты запросов.
